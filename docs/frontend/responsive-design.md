# Responsive design

**Status:** Binding for MVP target  
**Owner:** Product design  
**Reference when:** Building layout or choosing breakpoints.  
**Agent obligation:** Optimise the verified laptop target; do not claim mobile
or TV support without device testing.

## Target order

1. Laptop demo at 1280 x 720 or larger.
2. Common laptop sizes with browser chrome.
3. Laptop mirrored to a 16:9 TV.
4. Supporter/read-only surfaces on tablet/mobile after MVP.

Gameplay on a phone is not approved.

## Breakpoint rule

Choose breakpoints where the content fails, not from a framework's default
device names. Keep no more than three layout modes unless evidence requires
more:

- compact reading;
- laptop gameplay;
- wide/TV presentation.

## Gameplay layout

- Preserve the playfield aspect and cue lanes.
- Keep camera/calibration preview large enough for framing.
- Do not move Pause/Stop between common laptop widths.
- Letterbox decorative areas before shrinking cues or text.
- Keep score feedback peripheral to the cue target.

## TV mirroring

- Increase type and targets by viewing distance.
- Keep all interactions on the laptop; do not invent remote control support.
- Test overscan-safe margins and audio output.
- Mirroring is compatibility, not a separate application mode.

## Mobile supporter surfaces

When implemented, use a single-column priority stack, not squeezed desktop
cards. Charts must remain directly labelled and horizontally scroll only when
the data cannot be meaningfully summarised.
